Every request through the **Fastify** API carries a **correlation ID**, so a single operation can be traced across services and queues.

The **access-control module** combines role-based and attribute-based rules with **maker-checker** approvals across nine fintech roles: one person proposes a sensitive action and another approves it.

The **NIBSS utilities** generate and validate session IDs and transaction references. They were checked against real transaction samples, which surfaced discrepancies in the spec itself.

Documents go through an **OCR and field-extraction pipeline**: Google Cloud Vision reads the page, Claude tool use extracts the fields, and BullMQ runs the jobs.
